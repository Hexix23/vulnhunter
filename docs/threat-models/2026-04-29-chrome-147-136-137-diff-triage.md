## High-signal commits

### R1-C1 Blink AnimationTrigger map mutation

Commit: `1c93fde36884ca2474c0abdc5590cbcbcf1ab8dc`
Original commit: `a303ce665e047cd9a69806393081344f5a6f7caa`
Subject: `[M147] Copy HeapHashMap before iterate in AnimationTrigger::Perform*`
Files:
- `third_party/blink/renderer/core/animation/animation_trigger.cc`

Patch shape:
- `PerformActivate()` now copies `animation_behavior_map_` before iteration.
- `PerformDeactivate()` now copies `animation_behavior_map_` before iteration.

Invariant:
Any Blink GC map/vector/set that can be mutated by animation lifecycle side
effects must not be iterated live while calling methods on contained objects.

Variant targets:
- Other live iterations over `animation_behavior_map_`, especially
  `UpdateCompositorTriggerAnimations()`.
- Similar animation collections where `Animation` method calls can detach,
  finish, cancel, disassociate triggers, or run lifecycle tasks.

Priority: P1. Web-triggerable Blink feature, accepted stable cherry-pick, tiny
patch, clear invariant.

### R1-C2 Blink pseudo-element event target stale state

Commit: `95def1bd07956197f249712a35070ca3efda7d84`
Original commit: `82777e870bf03d3d0f5fa21dad8a9311a8a69d5b`
Subject: `[M147] Fix click dispatch for ephemeral hit-testable pseudo-elements`
Files:
- `third_party/blink/renderer/core/dom/pseudo_element.cc`
- `third_party/blink/renderer/core/events/pointer_event_factory.*`
- `third_party/blink/renderer/core/input/{mouse,pointer,touch}_event_manager.*`

Patch shape:
- PseudoElement removal now notifies EventHandler before parent clearing.
- Mouse/pointer/touch cached targets fall back to originating element.
- Click dispatch replaces disconnected pseudo-element mouse target.

Invariant:
Input state machines must not keep pseudo-elements as durable event targets
across synchronous style/layout mutations. Any target cache containing a
pseudo-element needs removal handling before the pseudo is orphaned.

Variant targets:
- Drag, pointer capture, hover boundary events, touch active targets,
  popover/light-dismiss and selection paths that cache pseudo-elements.

Priority: P1/P2. The fixed bug is interaction loss, but the stale-target class is
close to UAF-style lifetime mistakes.

### R1-C3 Viz hit-test hierarchy validation

Commit: `97dd88c8e2f9a04b55e4644e521c1d3b6e138c2e`
Original commit: `00116e7002fb40c113daaff72864bbe00590e28b`
Subject: `[M147] viz: Add hierarchy validation to HitTestAggregator`
Files:
- `components/viz/service/frame_sinks/frame_sink_manager_impl.*`
- `components/viz/service/hit_test/hit_test_aggregator.*`
- `components/viz/service/hit_test/hit_test_aggregator_delegate.h`

Patch shape:
- Aggregation now validates `FrameSinkId` parent-child relation before accepting
  child regions from submitted hit-test data.
- Invalid child regions are dropped from aggregate output but retained in
  manager state because browser hierarchy updates can race compositor frames.

Invariant:
Renderer/client submitted hit-test region graphs must be validated against the
browser-owned frame-sink hierarchy at aggregation time, not trusted from client
data.

Variant targets:
- Other consumers of submitted `HitTestRegionList` or `FrameSinkId` edges.
- Races where hierarchy update and compositor frame submission disagree.

Priority: P1 for compromised-renderer/browser-boundary model; P2 for pure web.

### R1-C4 HelpBubble teardown UAF hardening

Commit: `22fcaa0ec583c8a27c3bf55c78f0883ab9b39911`
Subject: `[147] "[User Education] Harden help bubble teardown"`
Files:
- `components/user_education/common/help_bubble/*`
- `components/user_education/views/help_bubble*`
- `ash/user_education/*`

Patch shape:
- Separates closing vs closed callbacks.
- Teardown paths early-exit after teardown starts.
- Views help bubbles can close synchronously.
- Registry avoids briefly retaining references to deleted bubbles.

Invariant:
UI callback lists must distinguish "closing" from "closed"; callbacks must be
safe if `this` is deleted during callback dispatch or widget teardown.

Priority: P2. Strong UAF smell, but weaker remote-web reachability.

### R1-C5 Dawn/Tint MSL bool vec3 layout

Chromium roll commit: `68ba233a543d25e75c30f1228dd3bafa2da96937`
Dawn commit: `049880d58d6636a819168c00f44f8a4ed1e33e51`
Subject: `[M147] [msl] Fix issue in FixTypeLayout without bool vectors.`
File:
- `src/tint/lang/msl/writer/raise/fix_type_layout.cc`

Patch shape:
- `array<vec3<bool>>` wrapper type must use packed `u32`, because Tint later
  converts bool vector elements to `u32`.

Invariant:
Shader layout-rewrite passes must preserve the post-lowering physical element
type, not the source WGSL logical type. Logical `bool` can become physical
`u32`; array/vec3 packing must reflect that.

Variant targets:
- Nested `array<array<vec3<bool>>>`, structs containing bool vec3 arrays,
  storage/workgroup/private address spaces, matrices or aliases that lower bool
  to integer after layout calculation.

Priority: P1 for WebGPU/Tint inappropriate implementation and possible backend
memory-layout mismatch.
