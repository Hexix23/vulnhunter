4. DelayLayerTreeViewDeletionOnLocalSwap is enabled by default.

Interpretation:

H10-H12 showed Release clears the leaked/cached manager when the Release directive
arrives. H20 narrows the reachability gap: Blink has normal product code paths
that delay Release while there are active view-transition animations or pending
waitUntil promises. That makes H15/H19 more interesting because the attacker
question becomes whether a page can create enough concurrent cross-document
transitions with large shared elements before Release arrives, not whether
Release is always immediate.

Remaining gap:

This is source-level reachability evidence, not a browser-level HTML PoC yet.
The next report-grade step is a browser/content shell test or manual Chrome
repro that starts cross-document view transitions with large shared elements and
delays transition completion via long animations or waitUntil promises, then
observes Viz/GPU memory growth.
